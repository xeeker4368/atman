Review of the B20+B21 budget task (approved). **No production code changed.**

## 1. The derived cap, and what changes for a user

**Derived maximum: 57,216 → 52,360 characters.** The configured cap stays **50,000**
(B6a's rounding down). **For a user, nothing changes today.**

## 2. The budget term, and the headroom with 9 tools

- **The term:** the full catalogue's schemas, 4,854 characters of JSON, are **1,214
  estimated tokens** at the window's 4.0 chars/token. The real tokenizer measured
  1,052, so the estimate errs in the safe direction.
- **Headroom beside a maximal message: ~590 tokens** (was ~1,804).

## 3. Proofs, now committed tests (`tests/test_history_window_b21.py`)

- **A turn that fits sends a byte-identical prompt.** Four fitting scenarios were run on
  the pre-B20 code, `cb6dafd`, exported to a scratch tree and run with the same
  interpreter, and on HEAD. Every model call (messages, tools, options) was hashed.
  - The scenarios: a single message; short history + records + a round of two calls;
    longer history + records + two rounds; records with continuation pieces + a round.
  - Both runs gave `fda59f47…`, per scenario and overall. That digest is pinned.
- **Window events leave every gate verdict byte-identical.** Every frozen case under
  four scripted replies: the trace the gate is handed in production
  (`call_entries` of the case's trace plus `records_shrunk`, `rounds_dropped` and
  `final_call_forced` markers) gives the same verdict JSON, advisory JSON and
  classifier prompt as the trace without them.
- **Proven to bite**, with `PYTHONDONTWRITEBYTECODE=1`:
  - removing `call_entries`' filter fails the gate proof, because the markers reach
    the classifier's prompt;
  - putting the pinned messages before older history fails the digest.

**Measured, and deliberately not pinned:** when a conversation is long enough that
older history is already windowed **and** tools are offered, the schema term leaves
room for **one fewer older message**:
- 60 messages of 2,000 chars: 18 → 19 omitted;
- 120 messages: 78 → 79 omitted.

With no tools offered it is identical. That is B20 working as intended, and the omitted
message stays retrievable.

**Older-history windowing stays unmarked**, as approved.

## A process finding, recorded

A first full-suite run after the bite proofs **failed two tests against code
byte-identical to HEAD**. The order-swap mutation was the same length as the original
and was restored within the same second, so Python kept running the mutated `.pyc`
(bytecode is validated by source size and mtime to the second). Clearing `__pycache__`
fixed it: **1,438 passed, 4 skipped**.

The same hazard could make a same-size mutation fail to take effect. Both proofs were
therefore re-run with bytecode writing off, and both still bite. Mutation runs use
`PYTHONDONTWRITEBYTECODE=1` from now on.
