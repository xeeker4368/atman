# 2026-10-06: the chat page (Phase 9, first row; decision #31)

**What changed.** A no-build chat page served by the app: `program/api/static/` (index.html,
app.css, app.js, render.js) at `GET /` and `/static/`. Three read routes behind `require_actor`
(`GET /api/me`, `/api/conversations`, `/api/conversations/{id}/messages`) and one plain read
query, `db.list_user_conversations`. A pure ASGI middleware puts the CSP, `nosniff` and
`no-referrer` on every response. Receipts render beside each reply, live and stored.
`creative_write`'s result line and description now say the person sees a note that a piece was
saved (prompt-facing; needs approval; `BEFORE_PIECE_2` re-taken in that commit).

**Why.** Decision #31 replaces #7's React plan for chat only; F50 owed the receipt rendering
and the `creative_write` line.

**Tested.** `tests/test_web_ui.py` (26): own data only, identical 404s, NULL and unreadable
traces, stored receipts equal live ones, two people at once with attribution in both stores,
headers on the page, assets and `/api` (including 401 and an unknown path), and static checks
on the page and scripts. Mutations: dropping the ownership check, the list's user filter, the
middleware, or returning `[]` for an unreadable trace each fail the tests. The renderer was run
against the hostile inputs in a throwaway node script outside the repo; the browser check is the
operator's.

**Known limits.** Logout forgets the token in this tab; it does not revoke it (tokens are
stateless, valid until expiry). No streaming. Loopback is where `start.sh` binds by default,
not something the code enforces. The trace panel is a display choice; the API trace itself
(both endpoints) replaces the entity's own writing with its length (`trace_view`, decision
#10): `creative_write`'s text, title and result, and a `memory_search` result holding a
creative-writing or journal record. The stored `tool_trace` is unchanged.
