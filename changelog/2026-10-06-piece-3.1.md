# 2026-10-06: piece 3.1 (classifier at temperature 0; render_corrections behind a setting)

**What changed.** `classifier.classify` overrides `temperature` with
`integrity.classifier_temperature` (new, bootstrap-only, 0.0) beside `num_predict`; `num_ctx` is
still the chat's (fix plan A1: a different value would reload the shared model). Both consumers,
the gate and the correction classifier, inherit it. The two eval headers now record the
classifier's temperature as `temperature`, with the chat value beside it as `chat_temperature`.
`retrieval.render_corrections` is a new settings-backed bool, **seeded on**. Off,
`_attach_supersessions` returns before the resolution query: no annotations and no
"check did not complete" note, in passive records and `memory_search` alike. The links are untouched.

**Why.** Fix plan 3.1 and ruling 1 (temperature 0). The brief allowed the setting only if its
default reproduced today's behaviour byte for byte. It does, so it is included, and the fix
plan's "default off" is not followed (that needs its own ruling after point A).

**Tested.** `tests/test_render_corrections.py`: a digest of the passive system prompt plus the
`memory_search` result over a fixed-clock, fixed-id scenario with a REPLACED and a CONTRADICTED
link, **taken on the code before the setting existed**, equals the default's and the explicit
on's; off renders neither annotation nor note, never runs the query, keeps the links, and a switch
takes effect live. `tests/test_classifier.py`: the options sent are exactly `num_predict` and
`temperature: 0.0`; a 0.9 chat temperature does not reach the merged options, and `num_ctx`
stays; a negative value raises; the key is not settings-backed. Mutations: dropping the
temperature, ignoring the setting, seeding it off in `defaults.toml`, or reporting off as a failed
check each fail tests.

**Known limits.** No frozen number is re-measured here; that is measurement point A
(`docs/DESIGN_GATE_ORDINARY_READING.md` Appendix F). The existing
`test_the_settings_are_bootstrap_only_not_live_editable` compares `spec.key` against dotted
names and can never fail; not fixed here, and the new key has a correct test.
