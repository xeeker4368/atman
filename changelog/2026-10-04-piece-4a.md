## Item 1: the live-test marker (first, as asked)
- `@pytest.mark.live("ollama" | "searxng" | "comfyui" | "internet")` replaces every `skipif(not <service>.is_available())` and the SearXNG, ComfyUI and example.com probes, which all ran **at import**. A live test is skipped unless `--run-live` is given; with it, the named service is probed when the test is about to run. Moltbook's live tests were already opt-in by environment variable and make no request at import; unchanged.
- **Proof that collection makes no network connection, with a decoy** (`tests/test_live_marker.py`). `tests/netwatch.py` is a pytest plugin that logs every socket `connect` and DNS lookup. *Control:* a module written the old way (an import-time `requests.get` of a local decoy server) is collected in a subprocess; the watcher logs the connect and the decoy server saw exactly one request (`/api/version`). *Subject:* the real suite is collected in a subprocess with the same watcher; the log is empty. Both ran before anything else.
- **A guard, so an unmarked test cannot reach the real Ollama either.** A wrapper on `requests.sessions.Session.request` refuses any request to loopback port 11434 (or the host configured at import) from collection or from a test without the marker, raising `OllamaGuardViolation` (a `BaseException`, recorded and re-reported at session end like the store guard). The failure tests that point `ANAM_OLLAMA_HOST` at port 1 are unaffected.
- **12 tests; mutations (7 killed, 1 equivalent):** guard off (send stubbed), `::1` not recognised, port check dropped, marker no longer skips, watcher stops logging, an old `skipif(is_available())` restored in `test_gate.py`: all killed. *Survived:* not resetting the allow flag after a live test; it is equivalent, because the autouse fixture sets the flag at the start of every test.

## Item 4: SQLite capability probe (instead of a version minimum)
`program/memory/capability.py::probe` builds `archive.sql`, `working.sql` and every migration (migration 8 included) in two in-memory databases and runs the notes index `integrity-check`; any `sqlite3.Error` becomes `SqliteCapabilityError` with a plain message that names the running version, the recorded `TESTED_SQLITE_VERSION` (3.53.1) and SQLite's own reason, and says nothing was written. It runs in the app's lifespan after the secret check and before `init_databases()`, so a refusal touches no file. It takes about 10 ms.
- No older SQLite was available. A build missing a feature is simulated with SQLite's authorizer (deny `CREATE VIRTUAL TABLE ... fts5`, deny `json_valid`), so the real engine refuses the statement.
- 7 tests (`tests/test_sqlite_probe.py`). **Mutations, all killed:** probe not called at startup; error not wrapped; migrations not run; notes index check dropped; probe writing a file; tested version dropped from the message (this one first survived, because the running and tested versions are both 3.53.1 here; the tests now use a distinct value).

## Item 5: a failed version read is not a version
