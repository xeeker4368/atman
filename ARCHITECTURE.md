# ARCHITECTURE.md

The current invariants of the system, one section per area. The section names are `BUILT.md`'s area headings, so a search of that frozen history by heading lands on the matching section here.

Each line says what the system does **now** and ends with where that is enforced or implemented. A citation is a path and a name joined by two colons: under `tests/` the name is a test that fails if the line stops being true; elsewhere it is the function or constant that does it. There is no history, date or measurement here; those are in `BUILT.md` (frozen), `changelog/` and `docs/`. A line with no citation is not in this file. Update it in the same commit as the change **only when an invariant changes** (`AGENTS.md` "Git hygiene").

This is not `program/integrity/architecture.md`, which is the fabrication gate's rubric.


## Core platform

- The application package is `program/`; routers are split by domain under `program/api/routes/` (auth, chat, health, upload). `program/api/app.py::create_app`
- Configuration is layered `config/defaults.toml` then `config/local.toml` then `ANAM_*` environment variables, deep-merged, and read at call time, never at import. `tests/test_config.py::test_merge_is_deep_not_wholesale_section_replacement` `tests/test_config.py::test_env_overrides_both_files` `tests/test_config.py::test_values_resolve_at_call_time_not_import_time`
- A bad configured value raises `ConfigError`; it never silently falls back to a default. `tests/test_config.py::test_bad_integer_env_raises_rather_than_silently_defaulting`
- OpenAPI and docs endpoints are disabled; `GET /api/health` reports liveness only. `tests/test_health.py::test_openapi_and_docs_are_disabled` `tests/test_health.py::test_health_returns_ok`
- Startup refuses to run without `auth.session_secret`, and does so before touching any store. `tests/test_startup.py::test_a_missing_secret_stops_startup_before_the_store_is_touched`
- A server holds its store's lock (an `flock` on `data_dir()/server.lock`) for its lifetime, taken after the secret check and the capability probe and before the databases are created; a second server on one store and a vector-writing script are both refused while it is held, and a killed holder leaves nothing to clear. `program/ops/store_lock.py::hold_for_server` `tests/test_store_lock.py::test_the_lock_is_taken_after_the_secret_check_and_the_probe` `tests/test_store_lock.py::test_a_second_server_on_one_store_is_refused` `tests/test_store_lock.py::test_a_second_process_is_refused_while_a_holder_lives` `tests/test_store_lock.py::test_a_killed_holder_leaves_no_lock_to_clear` `tests/test_store_lock.py::test_every_vector_writing_script_takes_the_lock`
- Startup creates and migrates both databases, then builds the vector store; a failing migration stops startup and changes nothing. `tests/test_startup.py::test_a_fresh_data_directory_is_initialised_and_login_fails_cleanly` `tests/test_startup.py::test_a_failing_migration_stops_startup_and_changes_nothing`
- Before any file is touched, startup builds the whole schema (archive, working, every migration, the notes index check) in an in-memory SQLite and refuses with SQLite's own error text and the observed passing and failing versions if this SQLite cannot; it checks capability, not a version number. `program/memory/capability.py::probe` `tests/test_sqlite_probe.py::test_the_probe_passes_here_and_builds_the_whole_schema` `tests/test_sqlite_probe.py::test_a_sqlite_missing_a_feature_is_refused_with_its_own_error` `tests/test_sqlite_probe.py::test_a_syntax_error_from_a_trigger_is_reported_as_what_it_was` `tests/test_sqlite_probe.py::test_startup_refuses_before_touching_the_store` `tests/test_sqlite_probe.py::test_the_probe_touches_no_file`
- An existing store is left as it is by startup. `tests/test_startup.py::test_an_existing_store_is_left_as_it_is`
- Direct dependencies are pinned to exact versions, with a `requirements.lock`, and each pin equals the installed version. `tests/test_requirements.py::test_every_direct_dependency_is_pinned_to_an_exact_version` `tests/test_requirements.py::test_the_lock_names_every_direct_dependency_at_its_pin`
- `run_server.py` serves `program.api.app:app` on the configured host and port; `start.sh` binds loopback unless `--lan` is given. `run_server.py::main` `start.sh::LAN_MODE`
- These are bootstrap-only and not in the settings registry: `agent.*`, `chat.max_message_chars`, the idle windows and the integrity classifier settings. `tests/test_settings.py::test_bootstrap_keys_are_not_settable` `tests/test_classifier.py::test_the_settings_are_bootstrap_only_not_live_editable`

## Memory / retrieval

- Two databases: `archive.db` holds exactly two tables and is never migrated; `working.db` holds the operational tables. `tests/test_db.py::test_archive_has_exactly_two_tables` `tests/test_migrations.py::test_archive_has_no_migration_path`
- Both are in `DELETE` journal mode, and a message reaches both stores in one transaction or neither. `tests/test_db.py::test_journal_mode_is_delete_on_both` `tests/test_db.py::test_failed_write_leaves_neither_store_touched`
- A Chroma reader made stale by another process's write is recovered once — the system cache is cleared, the client reopened, the query retried — and a second failure degrades the leg. The stale view that raises nothing is **not** detectable, which is why a vector-writing script is refused while a server runs. `program/memory/vectors.py::_recover_stale_reader` `tests/test_store_lock.py::test_a_second_process_writing_vectors_does_not_break_the_first` `tests/test_store_lock.py::test_the_recovery_retries_only_once` `tests/test_store_lock.py::test_a_stale_view_raises_nothing_which_is_why_a_script_is_refused` `tests/test_store_lock.py::test_the_chroma_stale_reader_recovery_api_exists`
- `chunks` is canonical and carries NOT NULL provenance; the FTS5 index follows it by trigger; vectors are derived and rebuildable. `tests/test_db.py::test_chunk_requires_provenance` `tests/test_db.py::test_fts_index_follows_chunk_insert` `tests/test_vectors.py::test_reconcile_repairs_every_missing_vector`
- Migrations are forward-only and transactional, run each statement through the caller's transaction (never `executescript`), and a failure leaves the version unrecorded. `tests/test_migrations.py::test_no_migration_uses_executescript` `tests/test_migrations.py::test_failed_migration_records_no_version` `tests/test_migrations.py::test_migration_six_failing_before_its_triggers_rolls_back_completely`
- Chunking has exactly two entry points, packs whole turns, never indexes the open trailing group, embeds before it writes, and never overwrites a chunk whose stored text differs. `tests/test_chunking.py::test_public_surface_is_exactly_two_functions` `tests/test_chunking.py::test_embedding_failure_writes_nothing_and_propagates` `tests/test_chunking.py::test_stored_text_mismatch_raises_rather_than_overwriting`
- A checkpoint never marks a conversation chunked; finalise writes the trailing group and marks it. `tests/test_chunking.py::test_checkpoint_never_marks_chunked` `tests/test_chunking.py::test_finalise_marks_chunked`
- A checkpoint of a conversation that has **ended** writes the trailing group too, and still does not mark it chunked: once ended no message can be added, so there is no open group to protect. `tests/test_lifecycle.py::test_a_checkpoint_on_an_ended_conversation_indexes_the_tail` `tests/test_lifecycle.py::test_a_checkpoint_on_an_open_conversation_still_leaves_the_tail_open`
- A chunk row whose vector is missing is re-embedded and upserted by the next chunking run of that conversation, rather than skipped on its stored text; a store that holds no vectors is not treated as missing them all. `tests/test_lifecycle.py::test_a_rerun_after_a_failed_upsert_writes_the_missing_vector` `tests/test_lifecycle.py::test_the_repair_does_not_run_against_a_store_that_holds_no_vectors` `tests/test_lifecycle.py::test_an_ordinary_checkpoint_repairs_nothing`
- Over-length input splits at paragraph, then line, then sentence, then whitespace, hard-cutting last and never corrupting multi-byte characters. `tests/test_splitting.py::test_prefers_paragraph_over_line_over_sentence` `tests/test_splitting.py::test_hard_split_never_corrupts_multibyte_characters`
- Retrieval is a lexical leg (FTS5/BM25) plus a vector leg (Chroma cosine) fused by reciprocal rank over ranks only, never raw scores. `tests/test_retrieval.py::test_fusion_uses_ranks_not_scores` `tests/test_retrieval.py::test_rrf_formula_is_reciprocal_rank_over_k_plus_rank`

- Provenance (`source_type`, `source_trust`) is returned but never scored. `tests/test_retrieval.py::test_provenance_is_returned_but_never_scored` `tests/test_retrieval.py::test_changing_source_trust_does_not_change_ranking`
- Relevance floors exist as a mechanism and ship unset; an unset floor is distinguishable from a set one. `tests/test_retrieval.py::test_floors_ship_unset_and_report_as_not_applied` `tests/test_retrieval.py::test_a_set_floor_is_distinguishable_from_an_unset_one`

## Known unverified

Taken from `BUILT.md`'s `[unverified]` bullets (132 of them; search that file by the heading named here). Absences are listed because no test can cite an absence.

- **Model plumbing:** KV-cache eviction behaviour at a genuinely saturated context.
- **Prompt assembly:** the 4.0 characters-per-token estimate under-counts dense content (code, JSON, tool traces) and has not been measured on any; the naming and trait checks are tripwires for known forms, not proofs; a single correct answer to the elapsed-time question is one observation, not the behavioural probe.
- **Memory / retrieval:** `db.connection()` can raise `database is locked` under sustained write contention (retry is in place; locking semantics are unchanged); `retrieval.rrf_k` and the other retrieval constants are judgment values; OR semantics admits stopword-only matches; the degenerate-query rule cannot fire while floors are unset.
- **Tools:** a large page can be truncated before the part that matters and the model cannot page further; the trace holds rendered text, not chunk ids; agent-written and web text is framed, not defended against.
- **Agent loop / chat:** a runaway reply is bounded by `num_predict`, not prevented; the four loop limits are judgment values.
- **Media:** `enabled` cannot be flipped at runtime (the default registry is cached); no duplicate detection and no edit or delete path for stored pieces; nothing prunes `workspace/`; image quality was not assessed.
- **Memory integrity:** the gate's accuracy is whatever the frozen sets measure and is not a guarantee; one case (`N7`) is unstable across sampling contexts; tool-claim prose outside the alias vocabulary is missed; the ACTION trigger is vocabulary-sensitive; `invented_id` flags a genuine artifact id (B19, in `NOW.md`).
- **Research / reflection:** the journal's live run covered scripted and invented corpora, not a real day; REPLACE-style statements skip DELETE triggers and nothing guards `chunks`, `messages` or the archive against them; a `notes` row's text is unguarded while it is active.
- **Correction / supersession:** CO10.2 and `PN9` are open (`NOW.md`); the person-corrects-entity call has never run in production; no real corpus holds corrections.
- **Admin / settings:** the settings read can degrade to the config seed for one call; the settings write checks type only, with no range or cross-setting check; there is no admin panel and no admin route.
- **Artifacts:** the vector store is not atomic with the rows; the duplicate-upload race is deferred (B9); an ingested file has no archive presence; a near-copy of a governance file is not caught.
- **Users / authentication:** no loopback gate exists; no TLS; no per-device token revocation.
- **Backup / restore:** a backup has never been restored; restore is not built.
